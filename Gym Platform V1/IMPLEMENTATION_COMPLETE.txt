  - Benefit: Supports both English and Arabic names

  - Standardized: ^01[0125][0-9]{8}$ across all DTOs

  - Benefit: Prevents future hire dates

  - Benefit: Prevents negative salaries

7. ASP.NET CORE VALIDATION PIPELINE
================================================================================

Request Flow:

  1. HTTP Request received
	 └─> POST /api/gym-owner-applications
		 Content-Type: application/json
		 Body: { "fullName": "...", "email": "..." }

  2. Model Binding
	 └─> Deserializes JSON to CreateGymOwnerApplicationRequestDto
		 If JSON parsing fails → 400 Bad Request (before validation)

  3. FluentValidation
	 └─> Discovers CreateGymOwnerApplicationRequestDtoValidator
		 └─> Executes 9 validation rules
		 └─> If any fails → 400 Bad Request with errors
		 └─> If all pass → continue to controller

  4. Authorization
	 └─> Checks JWT token
	 └─> Checks user role (if [Authorize] present)
	 └─> If fails → 401/403 Unauthorized/Forbidden

  5. Controller Action
	 └─> All model state is valid
	 └─> Request DTO is validated for shape/format/length

  6. Service Layer
	 └─> Business validation (uniqueness, existence)
	 └─> Database operations
	 └─> If fails → appropriate error response
	 └─> If succeeds → entity created

Result:
  ✓ Layered validation approach
  ✓ No duplicate validation logic
  ✓ Each layer has specific responsibility
